适用场景：算法功能开发、编程题需求落地、数组路径判断场景
二、需求背景
给定非负整数数组 arr，用户初始位于数组下标 start 处，可从当前下标 i 跳跃到 i + arr[i] 或 i - arr[i]（不可跳出数组）。需判断是否能跳跃到任一元素值为 0 的下标，解决数组内路径可达性判断问题。
三、产品目标
准确判断从起始下标 start 出发，能否到达数组中值为 0 的下标
处理边界场景（如数组仅 1 个元素、起始下标已为 0 等）
保证时间效率，避免重复遍历导致性能问题
输出结果为布尔值（true 可达 / false 不可达）
四、输入输出规则
1. 输入约束
表格
输入参数	约束条件	说明
arr	1 ≤ 长度 ≤ 5×10⁴；元素为非负整数，且 0 ≤ arr [i] < 数组长度	存储跳跃规则的核心数组，元素值决定跳跃步长
start	0 ≤ start < 数组长度	初始跳跃位置，需在数组有效下标范围内
2. 输出规则
输出类型：布尔值（true / false）
输出逻辑：若存在至少一条从 start 到 “值为 0 下标” 的有效路径，返回 true；反之返回 false
五、核心功能说明
1. 跳跃规则
从当前下标 i 出发，仅允许两种跳跃方向：
正向跳跃：目标下标 = i + arr[i]，需满足目标下标 < 数组长度
反向跳跃：目标下标 = i - arr[i]，需满足目标下标 ≥ 0
已访问过的下标不可重复访问（避免无限循环，如 arr = [1,1]，start=0 时反复跳跃）
2. 判断逻辑
初始检查：若 arr[start] == 0，直接返回 true（起始位置已满足条件）
遍历过程：使用 “标记访问” 机制（如额外数组、哈希集合）记录已访问下标
终止条件：
找到值为 0 的下标 → 返回 true
所有可跳跃路径遍历完毕仍未找到 → 返回 false
六、典型示例
表格
示例	输入参数	输出	核心说明
1	arr = [4,2,3,0,3,1,2]，start=5	true	存在路径：5→4→1→3（3 下标值为 0）
2	arr = [4,2,3,0,3,1,2]，start=0	true	存在路径：0→4→1→3（3 下标值为 0）
3	arr = [3,0,2,1,2]，start=2	false	所有可跳跃路径均无法到达值为 0 的 1 下标
4	arr = [0]，start=0	true	起始下标即为值 0 的下标
七、边界与异常场景处理
数组长度为 1：若元素为 0 则返回 true，否则返回 false（无其他跳跃方向）
跳跃越界：计算目标下标时，若超出 [0, 数组长度-1] 范围，该跳跃方向无效，不纳入遍历
循环路径：通过标记已访问下标，避免重复处理（如 arr = [2,1,1,2]，start=0 时，0→2→1→2，需标记 2 为已访问，避免反复遍历）
多 0 下标：只要到达任一值为 0 的下标，立即终止判断并返回 true
八、验收标准
功能正确性：所有典型示例及边界场景均返回正确结果
性能要求：处理最大长度（5×10⁴）数组时，执行时间 ≤ 1 秒，无内存溢出
逻辑完整性：覆盖 “可跳跃路径遍历”“访问标记”“越界过滤” 核心逻辑
异常处理：输入参数不满足约束时（如 start 超出数组范围），需提示错误信息
