# 智能体系统设计方案

## 1. 设计目标与范围
本设计方案面向“基于大语言模型的软件工程智能体”，覆盖需求分析、设计、实现、测试与自愈修复等软件生命连续阶段的编排，重点说明系统核心模块组织与业务控制流。

## 2. 系统核心架构与分层
本项目采用三层架构设计：
- **交互接口层 (`CLI`, `APIServer`)**：负责对外的交互入口暴露。CLI 支持轻量级脚本触发环境，APIServer (基于 FastAPI) 提供支持 VS Code IDE 插件调用的网络底层支持。
- **业务流核心层 (`AgentWorkflow`, `AgentState`, `GraphNodes`)**：系统的核心“大脑”。由基于 LangGraph 的有向图承载控制流流转，各个具体任务如生成架构、生成代码等皆浓缩为图上的单一节点函数（GraphNodes）；`AgentState` 则统一在这张图的节点间传递所有运行时上下文及过程资产。
- **模型与工具层 (`LLMClient`, `Tools`)**：基础设施层。LLMClient 统一封装对 DEEPSEEK_API 大语言模型等智能体的通信工作并完成结构化解析；Tools 负责隔离外部环境，执行硬盘读写（FileTools）和控制安全沙箱执行 Pytest 测试（Executor）。

## 3. 关键数据结构
- AgentState: 采用字典结构，统一在图节点间单向承载输入需求（Requirement）、生成产物（Design Models & Code）与测试结果断言（Test Result），支持隔离式多阶段状态流转与共享。

## 4. 设计模型
### 4.1 类图 (Class Diagram)
以 Package 分层概念将类文件结构进行映射抽象，清晰暴露代码之间的调用与组合关系，见同目录下 `class_diagram.puml`。

### 4.2 活动图 (Activity Diagram)
展现针对输入任务类型（`design`/`code`/`fix`/`full`），有向工作流中各业务动作按时序被调度的过程，并涵盖了受最大重试次数严格限定的“代码自愈闭环策略”，见同目录下 `activity_diagram.puml`。

## 5. 设计总结
系统通过 `AgentWorkflow` 进行全局宏观统筹，利用分离的 `GraphNodes` 高内聚地调用底层 `LLMClient` 完成逻辑生成推理，并在完成物理保存后回调 `Tools` 环境去执行运行测试。所有过程状态由 `AgentState` 携带。测试环节出现失败时，可平滑触发 `fix_code_node` 修补机制循环尝试保证交付质量，成功实现了对软件工程生命周期多任务协同的降维打击。
